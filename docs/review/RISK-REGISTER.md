# OVRA Engineering & Security Risk Register

**Document ID:** OVRA-RSK-001  
**Version:** 1.0.0  
**Date:** 2026-11-03  
**Status:** Active  

---

| Risk ID | Risk Category | Description | Severity | Likelihood | Mitigation Strategy | Owner Role | Release Gate |
|---|---|---|---|---|---|---|---|
| **RSK-01** | **Security / SSRF** | Workflows with HTTP Request nodes querying cloud metadata (`169.254.169.254`) or internal cluster services (`10.0.0.0/8`). | **Critical** | **High** | Mandatory SSRF Egress Gateway with strict pre-resolution DNS check, IP blocking of private/link-local ranges, redirect re-validation, and DNS rebinding pinning. | Security Architect | Phase 6 Release Gate |
| **RSK-02** | **Multi-Tenancy** | Cross-tenant data leakage if an application query omits `workspace_id` in WHERE clause. | **Critical** | **Medium** | Defense-in-depth: Dual enforcement with application RBAC + PostgreSQL Row-Level Security (RLS) scoped via transaction-local `set_config`. Mandatory automated cross-tenant negative test suite. | Principal Data Architect | Phase 2 Release Gate |
| **RSK-03** | **Security / Code Sandbox** | User submits malicious Python/JS code that escapes container and compromises the worker host or cluster. | **Critical** | **Medium** | Code nodes disabled by default for public multi-tenancy. Sandboxes use gVisor (`runsc`) userspace isolation on dedicated Kubernetes node pools with non-root, read-only rootfs, and zero ambient cloud credentials. External pentest required. | Infrastructure / Security Lead | Phase 7 Release Gate |
| **RSK-04** | **Execution Reliability** | Non-deterministic code inside Temporal Workflow functions (e.g. `Math.random()`, `Date.now()`, direct HTTP calls) causing replay panics. | **High** | **Medium** | Strict separation: Workflow interpreter logic is 100% deterministic graph navigation. All I/O, timers, and external calls relegated to Activities. Automated Temporal workflow linting and replay unit tests in CI. | Core Engine Lead | Phase 4 Release Gate |
| **RSK-05** | **Reliability / Duplicates** | Network timeout during external mutating API call causes duplicate transactions if retried blindly. | **High** | **High** | Enforce deterministic idempotency keys derived from execution ID + node ID. Tag uncertain responses as `OUTCOME_UNKNOWN` and pause or trigger automated status reconciliation instead of naive retries. | Integrations Lead | Phase 4 Release Gate |
| **RSK-06** | **Performance / Storage** | Large payloads (e.g., CSV files, images, PDFs) passed through Temporal workflow history exceeding Temporal 50MB/50k event limits. | **High** | **High** | Strict payload limit: Payloads >64KB automatically uploaded to S3-compatible storage. Workflow only passes immutable metadata envelope with storage key and SHA-256 hash. | Core Engine Lead | Phase 4 Release Gate |
| **RSK-07** | **Security / Credentials** | Third-party OAuth tokens or API keys exposed in application logs, error traces, or browser WebSocket frames. | **Critical** | **Medium** | Envelope encryption with Cloud KMS / Vault Transit. Worker lease model where secrets are decrypted only in-memory for active task duration. Global regex redaction in all logging and tracing pipelines. | Security Architect | Phase 2 & 6 Gates |
| **RSK-08** | **AI Agent Safety** | AI Agent node hallucinating parameters or executing unauthorized tool operations without bounds. | **High** | **Medium** | AI agents operate with explicit tool allowlists, strict JSON schema validation, token budget ceilings, max-step counters, and mandatory Human-in-the-Loop approval gates for sensitive actions. | AI Lead | Phase 9 Release Gate |
| **RSK-09** | **Compliance / Legal** | Non-compliance with Digital Personal Data Protection (DPDP) Rules 2025 regarding Indian user PII storage and breach notifications. | **High** | **Medium** | Default deployment in Indian cloud regions (Mumbai/Hyderabad). Configurable data retention policies (30-day default payload purge), PII masking, and full audit logging. Legal counsel sign-off. | Compliance Officer | Phase 10 Release Gate |
| **RSK-10** | **Operational / Noisy Neighbor** | Single tenant spawning 50,000 executions, exhausting worker task queues and starving other tenants. | **High** | **High** | Per-workspace concurrent execution limits, fair task queue scheduling, and token-bucket rate limiting at the API gateway and Temporal workflow submission layer. | Platform Engineer | Phase 4 & 5 Gates |
